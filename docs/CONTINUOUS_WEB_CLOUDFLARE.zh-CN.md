# Continuous Web 与 Cloudflare 操作指南

本指南是一份可复用的操作契约，不表示所有项目已经完成部署。

## 1. 分开四个层次

```text
私人源仓库
    -> 验证与构建
    -> Cloudflare 部署
    -> 读者访问策略
```

必须分别决定：

- 源文件隐私：规范源文件和原创作品是否私人；
- 部署身份：哪些凭据可以构建或部署；
- 读者访问：哪些人可以阅读已部署网页；
- 搜索可见性：搜索引擎是否可以索引。

改变其中一层，不得静默改变其他层。

## 2. 私人项目默认姿态

对于未发布或具有版权属性的作品：

1. 保持规范源仓库为私人仓库；
2. 使用私人 CI 或 Cloudflare 侧 Git 集成，不把源文件复制到公共仓库；
3. 只部署有意发布的渲染产物；
4. 使用 Cloudflare Access 或等效的服务端访问门保护读者访问；
5. 对受限材料关闭索引，并检查预览、资源、feed 和生成文件是否遵守同一访问策略；
6. 绝不提交密码、API token、包含密钥的访问策略或恢复码。

统一阅读密码可以作为迁移阶段的临时政策，但它本质上是共享秘密。项目变得敏感或需要多人访问后，应改用统一管理的访问策略、短期凭据或可单独撤销的身份。

## 3. 部署 profile

部署前必须选择并记录一种 profile：

- **提供商原生集成**：运维最简单；必须核验提供商托管凭据的实际范围，未验证时不能称为最小权限；
- **强化外部 CI**：GitHub Actions 或其他 CI 使用限制到目标 Worker/项目的账户 token，token 只放在 CI secret store；
- **未来/提供商特定 profile**：只有当前文档和真实测试确认支持后才能使用。

PPF 已有的安全 profile 文档记录了参考权衡。部署凭据和读者访问仍然是两个正交安全轴。

## 4. 必要配置顺序

1. 定义项目源仓库、输出目录、规范域名、可见性和保留策略；
2. 选择构建与部署 profile；
3. 创建或连接 Cloudflare 项目，不把秘密暴露给仓库；
4. 从仓库文件配置构建命令和输出路径；
5. 只使用配置自定义域名所需的临时权限；
6. 在未发布产物暴露前先配置读者访问；
7. 执行 preview 构建，验证 HTML、资源、feed、重定向、headers 和访问行为；
8. 只有人类批准发布状态后，才执行生产部署；
9. 将实际提供商状态、部署 revision、访问策略和验证结果写回私人项目状态；
10. 保留回滚路径：上一份已验证产物或 commit、访问策略回滚和域名路由回滚。

## 5. AI agent 要求

每次 Cloudflare 操作前，AI agent 必须说明：

- 准确的账户、项目和域名；
- 操作改变的是部署、DNS、路由、访问控制，还是仅仅读取；
- 凭据类型和最小权限范围；
- 哪一步需要人类登录或批准；
- 传输了哪些数据，哪些数据仍保持私人；
- preview 与 production 的验证项目；
- 回滚步骤和完成证据。

AI agent 不得要求人类把密码、API token、私钥或恢复码粘贴到聊天中。如果浏览器或提供商界面要求输入这些信息，应由人类直接完成。

## 6. 完成门

只有当仓库构建通过、部署 URL 在预期策略下可访问、受限内容不能匿名读取、公共内容没有被意外限制，并且已验证的提供商状态写回私人项目记录后，Continuous Web 配置才算完成。
